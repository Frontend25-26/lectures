Как работает SPA

MPA vs SPA

MPA

  • Каждый переход = HTTP-запрос
  • Сервер возвращает новый HTML
  • Страница перезагружается полностью
  • Видна белая вспышка

SPA

  • HTML загружается один раз
  • JS меняет DOM на месте
  • Данные - через API (JSON)
  • Мгновенные переходы

Что нужно для SPA-переходов

Перехватить клик
—>
Не делать переход, остановить дефолтное поведение ссылки
Обновить URL
—>
Поменять адрес в строке браузера без перезагрузки - History API
Обновить UI
—>
Показать нужный компонент / экран, загрузить данные
Обработать «назад»
—>
Как-то отследить навигацию браузера и обновить UI

History API

История браузера - это стек

Каждый переход добавляет запись. Браузер помнит позицию «указателя» в стеке. 

// Примерная структура стека после нескольких переходов:
[
  { url: '/home',       state: null },
  { url: '/products',   state: null },
  { url: '/products/42',state: { id: 42 } },  // ← текущая
]

// До HTML5: JS не мог менять URL без перезагрузки страницы
// History API даёт полный контроль над этим стеком
console.log(window.history); // объект History

Свойства

  • length
  • state
  • scrollRestoration

Методы

  • back() / forward()
  • go(n)
  • pushState() / replaceState()

history.length

Количество записей в стеке истории текущей сессии. 

// Открыли браузер —> перешли на /about —> перешли на /contact

console.log(history.length); // 3


// Нажали «Назад» - length не изменился,
// но указатель сдвинулся на одну позицию назад
console.log(history.length); // всё ещё 3

Максимальное значение зависит от браузера. Записи разных вкладок не смешиваются.

history.back() и history.forward()

// Эквивалент кнопок браузера <— и —>
history.back();    // сдвинуть указатель на −1
history.forward(); // сдвинуть указатель на +1

back()

  • Переходит на предыдущую запись
  • Ничего не делает, если уже в начале стека

forward()

  • Переходит на следующую запись
  • Ничего не делает, если уже в конце стека

Оба метода асинхронны

history.go(n)

Прыжок на произвольное количество шагов в любую сторону. 

history.go(-1); // то же, что back()
history.go(+1); // то же, что forward()

history.go(-3); // прыжок на 3 записи назад
history.go(2);  // прыжок на 2 записи вперёд

history.go(0);  // перезагрузка текущей страницы
history.go();   // тоже перезагрузка (аргумент по умолчанию 0)

Если n выходит за пределы стека - вызов игнорируется без ошибки

Так же асинхронна

pushState и replaceState

history.pushState(state, unused, url)
history.replaceState(state, unused, url)

state - Объект состояния = любой сериализуемый объект.
[Ограничение - 640 тысяч символов на сериализованное представление (Firefox)]

unused - This parameter exists for historical reasons

url - URL-адрес новой записи в истории. Данный параметр не является обязательным; если он не указан, будет использоваться URL текущего документа

pushState и replaceState

// PUSH - добавляет новую запись в стек
history.pushState({ id: 42 }, '', '/products/42');

// REPLACE - заменяет текущую запись
history.replaceState({ sort: 'price' }, '', '/products?sort=price');

Когда push?

  • Переход на новую страницу
  • Открытие карточки товара
  • Любой «осмысленный» переход

Когда replace?

  • Редирект (логин —> дашборд)
  • Фильтры / сортировка в URL
  • Исправление URL без смысла «назад»

history.state

Данные, прикреплённые к текущей записи стека. Сохраняются при перезагрузке страницы. 

// Читаем state текущей записи
console.log(history.state); // null - если не задавали

// После pushState state становится доступен
history.pushState({ page: 'catalog', filters: ['sale'] }, '', '/catalog');
console.log(history.state); // { page: 'catalog', filters: ['sale'] }

Сериализуется через structured clone - объекты и массивы ок, функции и DOM-узлы - нет

history.scrollRestoration

Управляет тем, восстанавливает ли браузер позицию прокрутки при навигации назад/вперёд. 

// Два возможных значения:
history.scrollRestoration = 'auto';   // по умолчанию - браузер сам скроллит
history.scrollRestoration = 'manual'; // SPA берёт управление на себя

Для SPA почти всегда нужен 'manual' - иначе браузер скроллит не туда

Событие popstate

// Срабатывает при переходе назад / вперёд (back, forward, go)
// НЕ срабатывает при pushState / replaceState
window.addEventListener('popstate', (event) => {
    console.log('Новый URL:', location.pathname);
    console.log('State записи:', event.state);
    renderPage(location.pathname);
});
  • Срабатывает только на навигацию по стеку (кнопки браузера или go/back/forward после выполнения)
  • При pushState / replaceState - не срабатывает, UI обновляем сами
  • event.state - объект, который был передан в pushState для этой записи

SPA-роутинг через History API

// 1. Перехватываем клики по внутренним ссылкам
document.addEventListener('click', (e) => {
    const link = e.target.closest('a[href]');
    if (!link) return;
    const href = link.getAttribute('href');
    if (!href.startsWith('/')) return; // внешняя ссылка - пропускаем

    e.preventDefault();
    history.pushState({}, '', href); // меняем URL без перезагрузки
    renderPage(href);                // обновляем UI
});

// 2. Реагируем на «Назад» / «Вперёд»
window.addEventListener('popstate', () => {
    renderPage(location.pathname);
});

// 3. Инициализируем текущий маршрут
renderPage(location.pathname);

Именно это делают библиотеки роутинга - только надёжнее и с реактивностью фреймворка

React Router

Базовая настройка

import { BrowserRouter, Routes, Route } from 'react-router-dom';

function App() {
    return (
        <BrowserRouter>
            <Routes>
                <Route path="/" element={<HomePage />} />
                <Route path="/products" element={<ProductsPage />} />
                <Route path="/products/:id" element={<ProductPage />} />
                <Route path="*" element={<NotFound />} />
            </Routes>
        </BrowserRouter>
    );
}

BrowserRouter подписывается на History API. Routes выбирает первый совпавший маршрут и рендерит его компонент.

Навигация в компонентах

import { Link, NavLink, useNavigate } from 'react-router-dom';

// Link - SPA-переход без перезагрузки (вместо <a>)
<Link to="/products">Каталог</Link>

// NavLink - автоматически получает класс active
<NavLink to="/cart"
    className={({ isActive }) => isActive ? 'active' : ''}>
    Корзина
</NavLink>

// useNavigate - программный переход
function LoginPage() {
    const navigate = useNavigate();

    const onLogin = async () => {
        await login();
        navigate('/dashboard', { replace: true }); // replace: редирект
    };
}

Чтение URL в компонентах

import { useParams, useSearchParams } from 'react-router-dom';

// Динамический сегмент: /products/:id
function ProductPage() {
    const { id } = useParams(); // '42'
}

// Query string: /products?category=shoes&sort=price
function ProductsPage() {
    const [params, setParams] = useSearchParams();
    const category = params.get('category'); // 'shoes'

    // Фильтр - replace, чтобы не засорять историю
    const handleSort = (sort) => setParams(
        { ...Object.fromEntries(params), sort },
        { replace: true }
    );
}

Вложенные маршруты и Outlet

<Routes>
    <Route path="/dashboard" element={<DashboardLayout />}>
        <Route index element={<Overview />} />
        <Route path="stats" element={<Stats />} />
        <Route path="settings" element={<Settings />} />
    </Route>
</Routes>

function DashboardLayout() {
    return (
        <div className="layout">
            <Sidebar />
            <main>
                <Outlet /> {/* контент дочернего маршрута */}
            </main>
        </div>
    );
}

Лейаут монтируется один раз - при переходах пересоздаётся только <Outlet>

Vue Router

Настройка в Vue

import { createRouter, createWebHistory } from 'vue-router';

const router = createRouter({
    history: createWebHistory(), // History API
    routes: [
        { path: '/',             component: HomePage },
        { path: '/products',     component: ProductsPage },
        { path: '/products/:id', component: ProductPage },
        { path: '/:pathMatch(.*)*', component: NotFound },
    ],
});

// main.js
app.use(router);

createWebHistory

  • History API, чистые URL
  • Нужен fallback на сервере

createWebHashHistory

  • Hash-роутинг (#/path)
  • Работает без настройки сервера

Навигация в Vue

<!-- router-link - аналог Link в React Router -->
<router-link to="/products">Каталог</router-link>

<!-- active-class автоматически на совпавшем маршруте -->
<router-link to="/cart" active-class="active">Корзина</router-link>

<!-- Место рендера текущего компонента -->
<router-view />


import { useRouter, useRoute } from 'vue-router';

const router = useRouter();
const route  = useRoute();

router.push('/dashboard');                            // push
router.replace('/dashboard');                         // replace
router.push({ name: 'product', params: { id: 42 } }); // именованный маршрут

const id = route.params.id;    // динамический сегмент
const q  = route.query.search; // query string

React Router vs Vue Router

React Router

  • <Link to="…">
  • useNavigate()
  • useParams()
  • useSearchParams()
  • <Outlet /> - вложенные маршруты
  • Маршруты в JSX или объектах

Vue Router

  • <router-link to="…">
  • useRouter().push()
  • useRoute().params
  • useRoute().query
  • <router-view /> - вложенные маршруты
  • Маршруты всегда в объектах

Концепции одинаковые - разный синтаксис. Знаешь одно - быстро освоишь другое.

Классический роутинг через папку pages/. Каждый файл - отдельный маршрут.

Новый роутинг через папку app/. React Server Components по умолчанию.

export default async function ProductPage({ params }) {

Server Components не попадают в JS-бандл клиента - меньше кода в браузере

API Routes

Next.js позволяет писать серверные эндпоинты прямо в проекте - без отдельного бэкенда.

Pages Router

// pages/api/users.ts
export default function handler(req, res) {
    if (req.method === 'GET') {
        res.json([{ id: 1, name: 'Alice' }]);
    } else {
        res.status(405).end();
    }
}

App Router (Route Handlers)

// app/api/users/route.ts
export async function GET() {
    return Response.json([{ id: 1, name: 'Alice' }]);
}

export async function POST(req) {
    const body = await req.json();
    return Response.json({ created: body });
}
  • Имя файла в App Router - route.ts (не page.tsx)
  • Экспортируем функции с именами HTTP-методов: GET, POST, PUT, DELETE
  • Удобно для BFF (Backend For Frontend) и прокси к внешним API

Pages Router vs App Router

Pages Router

  • pages/ - папка маршрутов
  • _app.tsx - глобальный лейаут
  • router.query
  • Все компоненты - клиентские по умолчанию
  • Простая модель данных
  • Стабильный, хорошо задокументирован

App Router

  • app/ - папка маршрутов
  • layout.tsx - персистентный лейаут
  • params
  • Меньше JS на клиенте
  • Сложнее граница Server/Client

App Router - будущее Next.js. Pages Router поддерживается, но новые фичи только в App Router.

Link и useRouter в Next.js

import Link from 'next/link';
import { useRouter } from 'next/navigation';

// Link - SPA-переход, prefetch по умолчанию
<Link href="/products">Каталог</Link>
<Link href={`/products/${id}`}>Товар</Link>

// Программная навигация
function LoginPage() {
    const router = useRouter();

    const onLogin = async () => {
        await login();
        router.push('/dashboard');    // push
        router.replace('/dashboard'); // replace
        router.back();                // назад
    };
}

Зачем Next.js для роутинга?

  • Нет ручной конфигурации - структура папок говорит за себя
  • layout.tsx: общий UI для группы страниц без дублирования
  • SSR/SSG из коробки (спойлер следующей лекции)
  • Prefetch ссылок - переходы мгновенные
  • Привязка к Next.js - не переносимо на другой стек
  • App Router усложняет границу Server / Client компонентов

Итоги

  • SPA-переход = перехватить клик + pushState + обновить UI + слушать popstate
  • push - осмысленный переход, нужна запись в истории
  • replace - редирект, фильтры в URL, «техническая» смена адреса
  • React Router и Vue Router - одни концепции, разный синтаксис
  • Next.js - файловый роутинг «из коробки» + SSR для React
