MPA

Multi-Page Application

MPA - как это работает?

Браузер
URL запрос
→
Сервер
Маршрутизация
→
БД / API
→
Сервер
Рендеринг HTML
→
Браузер
Готовая страница

Каждый переход - новый HTTP-запрос и полная перезагрузка страницы

MPA

  • Простая архитектура - всё на сервере
  • SEO из коробки - сервер отдаёт готовый HTML
  • Работает без JavaScript
  • Быстрая первая загрузка страницы

  • Полная перезагрузка при каждом переходе
  • Нельзя управлять фокусом и делать анимированные переходы
  • Плохой UX при частых действиях пользователя
  • Сложно реализовать богатый интерактивный интерфейс

MPA - примеры

Wikipedia, большинство CMS-сайтов (WordPress), интернет-магазины 2000-х

Хотелось: добавить интерактивности без перезагрузки страницы

PEMPA

Progressively Enhanced Multi-Page Application

PEMPA - идея

Берём MPA и добавляем JavaScript поверх него

MPA-основа
+
JavaScript
AJAX / fetch
→
Частичное
обновление DOM

Приложение работает без JS, но улучшается при его наличии

PEMPA

  • Нет полной перезагрузки страницы - используем fetch
  • Работает без JavaScript (progressive enhancement)
  • Плавные переходы и управление фокусом

  • Логика рендеринга дублируется: на сервере и на клиенте
  • Сложная синхронизация состояния между клиентом и сервером
  • Гонки запросов (race conditions) при множественных fetch
  • Тесная связь между API-роутами и клиентским кодом
  • Нет централизованного хранилища - состояние разбросано по коду

Проблема дублирования

Сервер

<!-- PHP / Jinja / etc -->
<ul>
  {% for item in items %}
    <li>{{ item.name }}</li>
  {% endfor %}
</ul>

Клиент (JS)

// Та же логика, только на JS
items.forEach(item => {
  const li = document.createElement('li');
  li.textContent = item.name;
  ul.appendChild(li);
});

Хотелось: один код рендеринга для всего

SPA

Single Page Application

SPA - решение

Убираем серверный рендеринг совсем - весь UI на клиенте

CDN
→
Браузер
Весь UI-код
⇄
REST API
только данные

Сервер отдаёт пустой index.html, дальше всё делает JavaScript

SPA

  • Нет дублирования - один код рендеринга на клиенте
  • Богатый интерактивный интерфейс
  • Разделение: фронтенд и бэкенд независимы
  • Быстрые переходы после первой загрузки

  • Огромный JS-бандл - медленная первая загрузка
  • Водопады запросов: HTML → app.js → page.js → fetch(данные)
  • Тяжело на слабых устройствах - весь рендеринг на CPU клиента
  • Сложное управление состоянием (30–50% кода типичного SPA)
  • SEO проблемы - поисковики видят пустой HTML

Водопад зависимостей

0 мс → Браузер получает пустой index.html
+200 мс → Загружается и выполняется app.js (роутер, библиотеки)
+400 мс → Определяется текущий роут, загружается page.js
+600 мс → Компонент монтируется, запрашивает данные через fetch
+800 мс → Пользователь наконец видит контент

Эволюция архитектур

MPA → Сервер рендерит всё. Просто, но нет интерактивности
PEMPA → MPA + AJAX. Интерактивность есть, но дублирование кода
SPA → Весь рендеринг на клиенте. Мощно, но медленный старт и сложное состояние
SSR / RSC → Возврат к серверному рендерингу + гидратация. Лучшее из обоих миров

React

Что такое React?

JavaScript-библиотека для создания пользовательских интерфейсов

Не фреймворк - только UI-слой

  • Создан в Facebook в 2013 году
  • Open source, MIT лицензия
  • Используется в Facebook, Instagram, Netflix, Airbnb, Twitter...

Ключевая идея

UI = f(state)

Интерфейс - это функция от состояния.
Изменилось состояние → React сам обновит DOM.

Императивно (DOM)

// Вы сами говорите КАК менять
const el = document.getElementById('count');
el.textContent = count + 1;

Декларативно (React)

// Вы описываете ЧТО должно быть
function Counter() {
  return <p>{count}</p>;
}

Какие бывают React-элементы?

React оперирует виртуальными элементами - описаниями того, что должно быть в DOM

React Element DOM

Соответствует HTML-тегу - попадает в реальный DOM

// JSX
const element = <h1 className="title">Привет!</h1>;

// Что на самом деле создаёт React
const element = React.createElement(
  'h1',
  { className: 'title' },
  'Привет!'
);

Маленькая буква → DOM-элемент: <div>, <span>, <h1>...

React Element Component

Ссылка на компонент - React вызовет его и получит DOM-элементы

// Компонент - функция, возвращающая JSX
function Title() {
  return <h1 className="title">Привет!</h1>;
}

// Использование - большая буква!
const element = <Title></Title>;

Большая буква → компонент. Это обязательное соглашение!

Виртуальный DOM

React-элементы складываются в виртуальное DOM-дерево - лёгкое JS-представление реального DOM

Virtual DOM

// Просто объект в памяти
{
  type: 'div',
  props: { className: 'app' },
  children: [
    { type: 'h1', props: {}, children: ['Привет'] },
    { type: Title, props: {} }
  ]
}

Real DOM

<!-- В браузере -->
<div class="app">
  <h1>Привет</h1>
  <h2 class="title">Заголовок</h2>
</div>

Как работает Virtual DOM

1. Рендер → React вызывает компоненты и строит новое виртуальное дерево
2. Diffing → Сравнивает новое дерево со старым, находит минимальный набор изменений
3. Commit → Применяет только реальные изменения в браузерный DOM

Манипуляции с реальным DOM дороги. Virtual DOM позволяет делать их минимально

JSX

JavaScript XML - расширение синтаксиса JS

Позволяет писать HTML-подобную разметку прямо в JavaScript-файле

JSX - правила

function Card() {
  const name = 'Мурзик';
  const isActive = true;

  return (
    // 1. Один корневой элемент
    <div className="card">
      {/* 2. Выражения JS в {} */}
      <p>{2 + 2}</p>

      {/* 3. Комментарии так */}
      <h2>{name}</h2>

      {/* 4. class → className */}
      <h3 className="abv">title h3</h3>
      
      {/* 5. Условный рендеринг */}
      {isActive && <span>Активен</span>}
    </div>
  );
}

JSX - все теги должны быть закрыты

В HTML некоторые теги можно не закрывать. В JSX - нельзя.

HTML (можно)

<img src="cat.png">
<input type="text">
<br>
<hr>

JSX (обязательно)

<img src="cat.png" />
<input type="text" />
<br />
<hr />

Теги без содержимого закрываются через /> - самозакрывающий синтаксис 

// Компонент тоже можно записать самозакрывающим тегом
<StudentList />          // ✅ короткая форма
<StudentList></StudentList> // ✅ длинная форма

JSX → JS

Babel компилирует JSX в обычный JavaScript:

JSX (пишем)

const el = (
  <div className="box">
    <p>Текст</p>
  </div>
);

JS (получаем)

const el = React.createElement(
  'div',
  { className: 'box' },
  React.createElement(
    'p', null, 'Текст'
  )
);

Компоненты

Строительные блоки React-приложения

Каждый компонент - независимая переиспользуемая часть UI

Props - аргументы компонента

Props (properties) - способ передать данные от родителя к дочернему компоненту

// Передаём props как атрибуты JSX
<Header title="Список студентов" count={42} />

// Принимаем как аргумент функции
function Header({ title, count }) {
  return (
    <div>
      <h1>{title}</h1>
      <span>{count} студентов</span>
    </div>
  );
}
  • Props только для чтения - компонент не должен их менять
  • Данные текут сверху вниз (от родителя к детям)
  • Можно передать что угодно: строки, числа, функции, другие компоненты

Классовый компонент

import React, { Component } from 'react';

class Welcome extends Component {
  render() {
    return (
      <h1>Привет, {this.props.name}!</h1>
    );
  }
}
  • Наследует React.Component
  • Обязательный метод render()
  • Props доступны через this.props
  • State через this.state и this.setState()

Функциональный компонент

// С ключевым словом function
function Welcome({ name }) {
  return <h1>Привет, {name}!</h1>;
}

// Стрелочная функция
const Welcome = ({ name }) => (
  <h1>Привет, {name}!</h1>
);
  • Просто функция, возвращающая JSX
  • Props - аргумент функции (деструктуризация)
  • Возвращает ReactElement | null

Классовый VS Функциональный

Классовый

  • Много бойлерплейта
  • Сложнее читать
  • Методы жизненного цикла
  • Проблемы с this
  • Устаревший стиль

Функциональный

  • Лаконичный код
  • Легче читать и тестировать
  • Хуки вместо lifecycle
  • Нет проблем с this
  • Рекомендуется

Зачем нужен key?

key помогает React понять, какой элемент изменился, добавился или удалился

  • ❌ Не использовать индекс массива - при переупорядочивании будут баги
  • ❌ Не генерировать ключ на лету: key={Math.random()} - перемонтирует компонент каждый раз
  • ✅ Использовать стабильный уникальный идентификатор: key={student.id}

Хуки

Что такое хуки?

Функции, с помощью которых можно «подцепиться» к состоянию и жизненному циклу React из функциональных компонентов

  • Работают только в функциональных компонентах
  • Имена начинаются с use
  • Нельзя вызывать внутри условий и циклов
  • Всегда вызываются в одном и том же порядке

useState

Добавляет переменную состояния к компоненту

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  //     ^значение  ^сеттер   ^начальное значение

  return (
    <div>
      <p>Счётчик: {count}</p>
      <button onClick={() => setCount(count + 1)}>
        +1
      </button>
    </div>
  );
}

useEffect

Синхронизирует компонент с внешней системой (API, таймеры, подписки)

import { useState, useEffect } from 'react';

function StudentList() {
  const [students, setStudents] = useState([]);

  useEffect(() => {
    // Запускается после каждого рендера
    fetch('/api/students')
      .then(r => r.json())
      .then(data => setStudents(data));
  }, []); // [] = только при монтировании

  return <ul>{/* ... */}</ul>;
}

useEffect - зависимости

// Запускается при каждом рендере
useEffect(() => { ... });

// Запускается один раз при монтировании
useEffect(() => { ... }, []);

// Запускается при изменении userId
useEffect(() => {
  fetch(`/api/users/${userId}`);
}, [userId]);

// С очисткой (таймеры, подписки)
useEffect(() => {
  const timer = setInterval(() => {}, 1000);
  return () => clearInterval(timer); // cleanup
}, []);

useRef

Ссылка на значение или DOM-элемент, не вызывающая ре-рендер

import { useRef } from 'react';

function InputFocus() {
  const inputRef = useRef(null);

  function handleClick() {
    // Прямой доступ к DOM-элементу
    inputRef.current.focus();
  }

  return (
    <>
      <input ref={inputRef} />
      <button onClick={handleClick}>Фокус</button>
    </>
  );
}

useCallback и useMemo

Кэшируют функцию/значение между рендерами

import { useCallback, useMemo } from 'react';

function App({ items }) {
  // Кэшируем функцию - не создаётся заново
  const handleClick = useCallback(() => {
    console.log('clicked');
  }, []); // пересоздать только при изменении зависимостей

  // Кэшируем тяжёлое вычисление
  const total = useMemo(() => {
    return items.reduce((sum, item) => sum + item.price, 0);
  }, [items]); // пересчитать только при изменении items

  return <div>Итого: {total}</div>;
}

Кастомные хуки

Позволяют выделить и переиспользовать общую логику компонентов

Кастомный хук - это просто функция, имя которой начинается с use

Пример: useFetch

// hooks/useFetch.js
import { useState, useEffect } from 'react';

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch(url)
      .then(r => r.json())
      .then(data => { setData(data); setLoading(false); })
      .catch(err => { setError(err); setLoading(false); });
  }, [url]);

  return { data, loading, error };
}

Использование useFetch

import useFetch from './hooks/useFetch';

function StudentList() {
  const {
    data: students,
    loading,
    error
  } = useFetch('/api/students');

  if (loading) return <p>Загрузка...</p>;
  if (error) return <p>Ошибка!</p>;

  return (
    <ul>
      {students.map(s => (
        <StudentItem key={s.id} {...s} />
      ))}
    </ul>
  );
}

Fragment

Что делать, если нужно вернуть несколько элементов без обёртки?

Проблема

// ❌ Нельзя - два корневых элемента
function App() {
  return (
    <h1>Заголовок</h1>
    <p>Текст</p>
  );
}

// ❌ Лишний div в DOM
function App() {
  return (
    <div>
      <h1>Заголовок</h1>
      <p>Текст</p>
    </div>
  );
}

Решение: Fragment

import { Fragment } from 'react';

// Длинная форма
function App() {
  return (
    <Fragment>
      <h1>Заголовок</h1>
      <p>Текст</p>
    </Fragment>
  );
}

// Короткая форма (используется чаще)
function App() {
  return (
    <>
      <h1>Заголовок</h1>
      <p>Текст</p>
    </>
  );
}

Fragment не добавляет лишних узлов в DOM

Fragment с key

При рендере списка фрагментов нужен key - используем длинную форму:

function DescriptionList({ items }) {
  return (
    <dl>
      {items.map(item => (
        <Fragment key={item.id}>
          <dt>{item.term}</dt>
          <dd>{item.description}</dd>
        </Fragment>
      ))}
    </dl>
  );
}

TypeScript в React

Зачем TypeScript?

TypeScript добавляет статическую типизацию в JavaScript

  • IDE подсказывает props и их типы автоматически
  • Ошибки находятся на этапе компиляции, не в браузере
  • Код проще читать и рефакторить
  • Стандарт де-факто в коммерческих React-проектах

Создать проект: npm create vite@latest my-app -- --template react-ts

Типизация компонента — вариант 1

Тип описывается отдельно, стрелочная функция с типизированными props

type StudentItemProps = {
  name: string;
  grade: number;
  isActive?: boolean; // ? = необязательный prop
};

const StudentItem = ({ name, grade, isActive = false }: StudentItemProps) => {
  return (
    <div className={isActive ? 'item item--active' : 'item'}>
      <span>{name}</span>
      <span>{grade}</span>
    </div>
  );
};

Типизация компонента — вариант 2

React.FC — специальный тип для функционального компонента

import { FC } from 'react';

type StudentItemProps = {
  name: string;
  grade: number;
  isActive?: boolean;
};

const StudentItem: FC<StudentItemProps> = ({ name, grade, isActive = false }) => {
  return (
    <div className={isActive ? 'item item--active' : 'item'}>
      <span>{name}</span>
      <span>{grade}</span>
    </div>
  );
};

FC<Props> явно указывает, что функция — React-компонент.
Минус: запрещает возвращать undefined, только JSX | null

Типизация useState

import { useState } from 'react';

type Student = {
  id: number;
  name: string;
  grade: number;
};

function StudentList() {
  // Явно указываем тип массива
  const [students, setStudents] = useState<Student[]>([]);

  // Тип выводится автоматически: boolean
